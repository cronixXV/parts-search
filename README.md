# 🔧 Поиск автозапчастей

Клиентское приложение для подбора автозапчастей и аналогов через API [Фаворит Автозапчасти](https://lk.favorit-parts.ru/static/wsprice.pdf). Подбор идёт в два шага: сначала производитель, затем предложения и аналоги.

**Стек:** React 18 · Redux Toolkit · Vite · Bootstrap 5 · ESLint · Prettier · архитектура FSD

## ✨ Возможности

- **Шаг 1.** Ввод артикула, автопоиск после паузы в наборе (или по Enter) и список производителей, выпускающих деталь.
- **Шаг 2.** Выбор бренда и таблица искомой позиции с аналогами: название, производитель, цена, остаток.
- Состояния загрузки, пустых ответов и ошибок (сеть, неверный ключ, превышен лимит запросов, некорректный ответ).
- Защита от гонок: устаревшие запросы отменяются и не перезаписывают актуальные данные.

## 🚀 Быстрый старт

```bash
npm install
npm run dev
```

Приложение откроется на http://localhost:5173

| Команда            | Что делает                  |
| ------------------ | --------------------------- |
| `npm run dev`      | запуск dev-сервера          |
| `npm run build`    | production-сборка в `dist/` |
| `npm run preview`  | просмотр собранной версии   |
| `npm run lint`     | проверка ESLint             |
| `npm run lint:fix` | проверка и автоисправление  |
| `npm run format`   | форматирование Prettier     |

## ⚙️ Настройка

API-ключ лежит в `.env`:

```env
VITE_API_KEY=00000000-0000-0000-0000-000000000001
```

Это тестовый ключ из документации.

### Прокси

API работает по `http` и не отдаёт CORS-заголовки, поэтому запросы идут через прокси Vite:

```
/api/hs/hsprice/  →  http://api.favorit-parts.ru/hs/hsprice/
```

Прокси настроен в `vite.config.js` для `dev` и `preview`. Для production нужен такой же прокси на стороне веб-сервера, например в nginx:

## 🧱 Архитектура (FSD)

```
src/
├── app/                  инициализация: store, провайдер, корневой компонент
├── pages/
│   └── search/           страница; связывает фичи между собой
├── features/
│   ├── search-brands/    шаг 1: форма поиска, список брендов, slice
│   └── select-brand/     шаг 2: таблица предложений, slice
├── entities/
│   └── part/             работа с API деталей, нормализация ответа
└── shared/
    ├── api/              http-клиент и обработка ошибок
    ├── ui/               Loader, ErrorAlert, EmptyState
    └── lib/              useDebounce
```

Импорты идут только сверху вниз (`app → pages → features → entities → shared`). Фичи ничего не знают друг о друге, их связывает страница через props. Для межслойных импортов настроен алиас `@` → `src`.

Слой `widgets` не используется: страница одна, а составных блоков, которые нужно переиспользовать, нет.

## 🔄 Как это работает

```
ввод артикула ──▶ loadBrands ──▶ список брендов
                                      │ клик по бренду
                                      ▼
                               loadOffers ──▶ таблица: искомая позиция + аналоги
```

Запросы к API:

| Шаг         | Параметры                                            |
| ----------- | ---------------------------------------------------- |
| Бренды      | `?key=…&number=<артикул>`                            |
| Предложения | `?key=…&number=<артикул>&brand=<бренд>&analogues=on` |
